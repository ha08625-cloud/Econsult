# Offline encoder-training dependencies. NEVER installed in production.
#
# The Dockerfile installs requirements.txt only, and nothing under app/ imports
# scripts/encoder_training or scripts/synthetic_data
# (tests/test_encoder_training_dataset.py::test_app_never_imports_the_offline_tooling
# asserts it, for any scripts.* import, which covers scripts/training_gui too).
# Keeping these out of requirements.txt is what stops a ~2.5GB
# torch wheel and its CUDA runtime from entering an image that serves forms.
#
# CI's unit job does not install this file either. That is deliberate: the
# stdlib-only modules (dataset.py, metrics.py, decision.py, report.py) carry the
# logic that decides what an evaluation number *means*, and they are covered on
# an ordinary runner with no GPU. Tests that need scikit-learn skip themselves.
#
#   pip install -r requirements-ml.txt
#
# ---------------------------------------------------------------------------
# Python 3.12
# ---------------------------------------------------------------------------
# Pin the interpreter to 3.12, matching CI's unit job. The repo already floors
# at 3.12 (scripts/synthetic_data/recombine.py uses PEP 695 generics), and torch
# cu128 wheels are reliable on 3.12 and patchier on 3.13/3.14.
#
# On 3.11 the failure does not look like a version problem. Every command in
# scripts.encoder_training -- including smoke-cuda, which touches neither torch
# nor the generator -- imports the generator's CLI for one constant, so the whole
# package dies at import with:
#
#   File "scripts/synthetic_data/recombine.py", line 291
#       def _weighted_draw[KeyT](
#   SyntaxError: expected '('
#
# That is Python 3.11 meeting 3.12 syntax, not a bad torch wheel. Install this
# file into a 3.12 environment rather than lowering the floor: app/core/settings.py
# uses the same syntax, so the alternative is editing production code to
# accommodate a local interpreter. The training tooling imports nothing from
# app/, so the environment needs this file alone -- requirements.txt is not
# required for a training run.
#
# ---------------------------------------------------------------------------
# The run console (scripts/training_gui)
# ---------------------------------------------------------------------------
# The console starts training subprocesses with the interpreter it is itself
# running under, so it has to live in *this* environment -- the one with torch.
# That is why two web pins appear in a file whose whole point is that it is
# never installed in production: fastapi and uvicorn are here for a page that
# is served on localhost to the machine with the GPU, not for app/.
#
# They are pinned at exactly the versions requirements.txt pins, and
# tests/test_training_gui.py::test_fastapi_and_uvicorn_pins_match asserts the
# two files agree. Drift here would otherwise be discovered during a run
# rather than before one.
#
# ---------------------------------------------------------------------------
# Blackwell (RTX 5070) warning -- read before installing torch
# ---------------------------------------------------------------------------
# The RTX 5070 is compute capability sm_120 and needs a wheel built against
# CUDA 12.8 or later. An older wheel installs cleanly, imports cleanly, and then
# fails at the first kernel launch with "no kernel image is available for
# execution on the device". This is the single most likely thing here to eat an
# afternoon, and the failure looks nothing like a wheel problem.
#
# The good news, checked rather than assumed: the torch 2.13.0 wheel on PyPI's
# *default* index is a CUDA 13.0 build (`torch.version.cuda == '13.0'`), which
# covers sm_120. So a plain `pip install -r requirements-ml.txt` is expected to
# work on the 5070 and no special index is needed for this pin.
#
# If a version has to be downgraded for any reason, take it from the cu128 index
# rather than PyPI's default, because older default wheels are cu12.4 or earlier
# and will not run on this GPU:
#
#   pip install torch --index-url https://download.pytorch.org/whl/cu128
#
# Verify before training, not after:
#
#   python -m scripts.encoder_training smoke
#
# That subcommand prints torch's CUDA version and the device's compute
# capability (expect (12, 0) on the 5070) and then runs a real matmul. The matmul
# is the part that matters: `torch.cuda.is_available()` returns True on a wheel
# that cannot launch a single kernel, so an import-only check proves nothing.
#
# ---------------------------------------------------------------------------
# What CI does and does not see
# ---------------------------------------------------------------------------
# Nothing here is installed by CI, so the torch-dependent tests in
# tests/test_encoder_training_arm_a.py skip themselves there. The tests that
# cover the *silent* failure modes -- above all the embedding cache key, where a
# stale hit produces plausible numbers and no warning -- are stdlib-only and run
# on every commit. Installing this file locally is what turns the rest on.

# --- Task 3: baselines -----------------------------------------------------
scikit-learn==1.9.0

# --- Tasks 4 and 5: Arm A (frozen probe) and Arm B (fine-tune) --------------
# Pinned to the versions both arms were written and tested against.
# transformers 5.x is a deliberate choice rather than an accident of resolution:
# it is what the tokeniser-casing probe and the local-model paths in
# tests/test_encoder_training_arm_{a,b}.py were verified on.
#
# Arm B needs nothing here that Arm A did not: it unfreezes the model it already
# had. No bitsandbytes, no peft, no accelerate -- the plan's memory arithmetic
# says BERT-base at batch 32 / seq 256 fits in 12GB with room to spare, so a
# dependency bought to save memory would be a dependency bought for nothing.
torch==2.13.0            # PyPI default wheel is a cu130 build; see the note above
transformers==5.16.1

# --- compare-models: other base encoders ------------------------------------
# Everything here trains on `roberta-base` (arch_encoder_training.md section 4a),
# whose tokeniser needs nothing beyond what `transformers` installs.
#
# `compare-models` takes any BERT-base-sized encoder (hidden size 768, which
# model.py asserts). Some need more than this file provides: a SentencePiece
# tokeniser, for instance, fails at load with a message about a conversion
# rather than about a missing package, and wants `pip install sentencepiece
# protobuf`. Left uninstalled rather than pinned blind — neither package is
# needed by anything else here, and a pin nobody has run is worse than an
# instruction.

# --- the local run console (scripts/training_gui) ---------------------------
# Mirrors requirements.txt exactly; see the note above. Do not bump one file
# without the other.
fastapi==0.141.1
uvicorn==0.52.4
