# Offline encoder-training dependencies. NEVER installed in production.
#
# The Dockerfile installs requirements.txt only, and nothing under app/ imports
# scripts/encoder_training or scripts/synthetic_data (tests/test_wiring.py
# asserts it). Keeping these out of requirements.txt is what stops a ~2.5GB
# torch wheel and its CUDA runtime from entering an image that serves forms.
#
# CI's unit job does not install this file either. That is deliberate: the
# stdlib-only modules (dataset.py, metrics.py, decision.py, report.py) carry the
# logic that decides what an evaluation number *means*, and they are covered on
# an ordinary runner with no GPU. Tests that need scikit-learn skip themselves.
#
#   pip install -r requirements-ml.txt
#
# ---------------------------------------------------------------------------
# Python 3.12
# ---------------------------------------------------------------------------
# Pin the interpreter to 3.12, matching CI's unit job. The repo already floors
# at 3.12 (scripts/synthetic_data/recombine.py uses PEP 695 generics), and torch
# cu128 wheels are reliable on 3.12 and patchier on 3.13/3.14.
#
# ---------------------------------------------------------------------------
# Blackwell (RTX 5070) warning -- read before installing torch
# ---------------------------------------------------------------------------
# The RTX 5070 is compute capability sm_120 and needs a wheel built against
# CUDA 12.8 or later. An older wheel installs cleanly, imports cleanly, and then
# fails at the first kernel launch with "no kernel image is available for
# execution on the device". This is the single most likely thing here to eat an
# afternoon, and the failure looks nothing like a wheel problem.
#
# The good news, checked rather than assumed: the torch 2.13.0 wheel on PyPI's
# *default* index is a CUDA 13.0 build (`torch.version.cuda == '13.0'`), which
# covers sm_120. So a plain `pip install -r requirements-ml.txt` is expected to
# work on the 5070 and no special index is needed for this pin.
#
# If a version has to be downgraded for any reason, take it from the cu128 index
# rather than PyPI's default, because older default wheels are cu12.4 or earlier
# and will not run on this GPU:
#
#   pip install torch --index-url https://download.pytorch.org/whl/cu128
#
# Verify before training, not after:
#
#   python -m scripts.encoder_training smoke
#
# That subcommand prints torch's CUDA version and the device's compute
# capability (expect (12, 0) on the 5070) and then runs a real matmul. The matmul
# is the part that matters: `torch.cuda.is_available()` returns True on a wheel
# that cannot launch a single kernel, so an import-only check proves nothing.
#
# ---------------------------------------------------------------------------
# What CI does and does not see
# ---------------------------------------------------------------------------
# Nothing here is installed by CI, so the torch-dependent tests in
# tests/test_encoder_training_arm_a.py skip themselves there. The tests that
# cover the *silent* failure modes -- above all the embedding cache key, where a
# stale hit produces plausible numbers and no warning -- are stdlib-only and run
# on every commit. Installing this file locally is what turns the rest on.
