Phase 6B — HTTP API Contracts

Purpose

Define the exact HTTP interface for the Phase 6 session-backed form engine.

This document translates Phase 6A semantic invariants into concrete, enforceable wire contracts

---

Scope

This phase defines:
Endpoint list and responsibilities
Request and response schemas
Versioning and concurrency requirements
Error taxonomy and status code usage
Boundary-level invariants


This phase explicitly does not define:

Web framework

Persistence backend

Authentication or authorisation

Retention policies

Advisory (non-blocking) messages



---

Global API principles

All endpoints are JSON over HTTP

All requests and responses use UTF-8 encoded JSON

The server is authoritative for all state

The client never submits projections or derived state

All failures are explicit and non-silent

APIs are synchronous and request/response only



---

Session identity and versioning

Session identifier

runtime_id uniquely identifies a session

Generated by the server

Opaque and unguessable

Required for all endpoints except /form/init


Versioning

Each session has a monotonic integer version

Version numbers are scoped to a single runtime_id

The latest version is the highest version number for that session


Concurrency control

All mutating endpoints require a base_version

If base_version does not equal the latest version, the request fails

No automatic merging or retry semantics exist



---

Endpoint definitions

POST /form/init

Request body

{
  "condition_id": "string",
  "free_text": "string | null"
}

Request invariants

condition_id must reference a valid ruleset

free_text may be null

No other fields are permitted


Response body

{
  "runtime_id": "string",
  "version": 1,
  "client_state": ClientStateView
}

Response invariants

version is always 1

client_state is a render-only projection


Failure modes

400 Bad Request — malformed payload

404 Not Found — unknown condition_id

422 Unprocessable Entity — ruleset validation failure

---

POST /form/update

Request body

{
  "runtime_id": "string",
  "base_version": number,
  "answers": {
    "answer_key": "value"
  }
}

Request invariants

runtime_id must reference an existing session

base_version must be provided

answers must be present and completed

Only answer_key → value pairs are permitted

Any presence of projection or metadata fields is rejected


Response body

{
  "runtime_id": "string",
  "version": number,
  "client_state": ClientStateView,
  "safety_messages": [
    {
      "rule_id": "string",
      "message": "string"
    }
  ]
}

Response invariants

version is strictly greater than base_version

client_state reflects the newly created version

safety_messages contains all triggered blocking rules


Failure modes

400 Bad Request — malformed payload or illegal fields

404 Not Found — unknown runtime_id

409 Conflict — version mismatch

422 Unprocessable Entity —

incomplete required answers

illegal provenance transition

ruleset hash mismatch - If ruleset hash in DB ≠ current ruleset hash → 422




---

POST /form/finish

Request body

{
  "runtime_id": "string",
  "version": number
}

Request invariants

runtime_id must reference an existing session

version must equal the latest version


Response body

{
  "submission_id": "string"
}

Failure modes

400 Bad Request — malformed payload

404 Not Found — unknown runtime_id

409 Conflict — version mismatch or session already closed



---

ClientStateView contract

ClientStateView is a render-only projection and must never be accepted as input.

Properties

Derived from RuntimeState

Lossy by design

Safe for client rendering only


Allowed fields (illustrative)

question text

answer_key

current value

required flag

suggested flag


Enforcement rule

For each endpoint, define the exact accepted shape, and reject everything else.
For example, /form/update:
Allowed top-level keys:
runtime_id
base_version
answers
Inside answers:
keys must be valid answer_keys
values must match the declared answer type

---

Error model

All error responses use the following structure:

{
  "error": {
    "code": "string",
    "message": "string"
  }
}

Error code principles

Codes are stable and machine-readable

Messages are human-readable

No stack traces or internal details are exposed


Example error codes

INVALID_PAYLOAD

UNKNOWN_RUNTIME_ID

VERSION_CONFLICT

INCOMPLETE_ANSWERS

ILLEGAL_PROVENANCE_TRANSITION

RULESET_VALIDATION_FAILURE



---

Boundary invariants

The HTTP boundary enforces the following invariants:

RuntimeState never leaves the server

Projections never re-enter the server

All submissions are complete

All conflicts are explicit

All safety rules are evaluated exactly once per RunTimeState version created at POST /form/update submission

No silent recovery or auto-correction occurs
